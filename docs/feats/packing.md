# 容器排布与收纳空间选择

> Parent: [../index.md](../index.md)
> Related: [tag-grammar.md](tag-grammar.md)、[../requirements.md](../requirements.md)

玩家点击排序后，整理会压紧容器内布局；按 tag 收纳时也会尝试重排目标容器，
使散碎空位能够容纳新物品。折叠与堆叠补充先执行，最终排布在收纳结束后执行。

## 行为契约

### 范围与锁

- 排布范围为当前根容器与带有效 tag 规则的子容器，Locked 子树跳过。
- 未打规则的容器内部不动；可以遍历它们以找到更深层带规则的目的地。
- Pinned 与 Locked 物品的位置、转置保持不变，作为固定障碍。
- 目标容器原有物品全部保留，不能为了装入面积更多的新物品而把它们移出或丢弃。
- 物品不重叠、不越界；只允许游戏支持的转置、过滤与移动。

### 优先级与目标

规则之间沿用 tag 的全局优先级。每条规则先补充已有堆叠，再选择收纳候选。
同一规则下以放入面积更多为首要目标，面积相同时尽量向上压紧、减少占用行数。
未选中或游戏拒绝的候选继续尝试后续规则，不在不同优先级之间交换物品来提高面积。

排布只接收现有物品时，要求全部保留；减少占用行数是优化目标。
这里的高度只统计可移动物品；固定物品作为障碍占格，不能因其位于仓库底部，
就判定上方布局已最优。高度以内的可用空间须扣除实际覆盖的固定障碍。
面积与占用行数相同时，仍执行常规归拢与同模板排序。
当前布局比常规排序利用率更好时保留当前布局；求解器只有进一步改善时才替换基线。

### 有限等待与失败

- 每个网格的单次求解最多分配 1 秒，一次整理中的收纳与最终排布共享 3 秒求解预算。
- 已证明达到最优，或已有布局达到面积与行数的理论界限时，可以提前结束。
- 达到时限时采用已有可行结果；没有改进时使用原布局或启发式保底。
  不把限时得到的可行解宣称为全局最优。
- 求解在后台执行，游戏对象读取、布局应用和移动事务在游戏线程执行。
- 预算约束求解工作；原生库首次初始化、线程调度和游戏事务仍有额外开销，
  不承诺整次整理在 3 秒内结束。
- 腾出位置失败时不执行依赖该布局的收纳；移动失败的物品留在来源容器。
  已成功完成的重排与其他移动保留，不做整次整理的回滚。

## 示例

| 场景 | 预期 |
| --- | --- |
| 空位总面积够，但没有连续空间放入大件 | 尝试重排原有物品，再收进大件 |
| 3×3 空网格，候选为一个 2×2 与三个 1×3 | 优先放入三个 1×3，占满 9 格 |
| 3×3 内原有一个 2×2，另有三个 1×3 候选 | 保留原有 2×2，不为填满而移出它 |
| 容器已满，但已有堆叠未满 | 先补充数量，再考虑余量是否有位置 |
| 再次整理，常规排序或更优布局已稳定 | 不提交位置没有变化的排布 |
| 底部固定物品使总行数无法减少 | 上方散放物品仍正常归拢、排序 |
