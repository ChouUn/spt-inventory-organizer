## 目标

点击容器面板的排序按钮，由本 mod 统一完成折叠、合并堆叠、按 tag 收纳与排布。
完成后玩家能观察到：可折叠武器已折叠，物品按规则进了容器，容器内布局紧凑，
Pinned 与 Locked 物品原地不动。

## 范围

### 包含

工程骨架、tag 解析与测试、tag 编辑提示与长度放宽、替换排序按钮、
快照与游戏适配、折叠、收纳、启发式排布、UIFixes 入口兼容、合并堆叠、CP-SAT 排布。

### 不包含

服务端组件、FiR 条件、预览与撤销、战局内可用、角色装备整理、发布打包与版本检查。

## 实现方案

- 工程面向 net481：OR-Tools 没有 netstandard2.0 目标，Core 只能选 net462 以上。
  测试工程用 xunit，在 Windows 的 dotnet 上跑。
- Plugin.Tests 链接实际兼容源码并使用本机 Harmony，独立验证补丁共存与精确移除，
  不加载 Unity 或游戏程序集；完整 Plugin 仍通过解决方案构建检查。
- Plugin 用 RID win-x64，OR-Tools 原生库随构建进入输出目录，整目录部署到
  `BepInEx/plugins/ChouUn.InventoryOrganizer/`。游戏程序集经 `SPT_DIR` 引用，不入库。
- Bootstrap 在 Awake 最早处按绝对路径 LoadLibraryEx 加载原生入口，
  使用 DLL_LOAD_DIR 与 DEFAULT_DIRS 从插件目录解析依赖。
  游戏内延迟求解曾出现入口加载失败，不能仅依赖启动时设置全局搜索目录。
- 排序按钮的替换点是 `GridSortPanel` 的点击处理，依据是折叠与锁的调研报告。
- UIFixes 兼容在 Plugin 侧实现：等待其补丁注册完成，核对目标与具体补丁方法后，
  精确移除 `GridSortPanel.Sort` 上的 `StackFirstPatch.Prefix`。
  不修改其配置、不移除其他补丁，也不调用其私有 `StackAll` 或 `Sort`。
- 合并堆叠使用游戏的匹配、合并与事务 API，由 Core 编排、GameAdapter 执行。
  按 F8 处理范围和锁；通过 IsSameItem 与 TransferOrMerge 模拟后提交事务，
  保留游戏当前的同类判定，不调用 UIFixes 私有合并实现。
- 收纳与最终排布共用 CpSatPacker：大件用可选矩形，1×1 只建数量变量并在求解后填空。
  用游戏当前位置与启发式建立保底解；先最大化面积，再最小化占用高度。
  原有物品必留，固定物品不入可移动候选；只采纳优于保底的结果。
  常规启发式排序与当前位置利用率相同时选常规排序，保留仓库归拢及同模板排序行为。
- 按网格分解求解，每次最多 1 秒，收纳与最终排布累计最多分配 3 秒。
  多网格容器按原网格顺序分别选取候选，不承诺跨网格联合最优。
  求解放到后台，游戏读取与事务在原上下文继续；预算耗尽后仍可用保底结果完成整理。
- 收纳先应用目标原有物品的腾位布局，再以游戏 Move 的 simulate 与事务逐项精确移入。
  此流程复用已验证的布局事务，不将跨容器移动伪装为原生排序。
