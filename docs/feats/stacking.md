# 统一堆叠与跨容器补充

> Parent: [../index.md](../index.md)
> Related: [../requirements.md](../requirements.md)、[packing.md](packing.md)

一次整理先折叠，再统一处理容器内及跨容器堆叠，然后进入收纳与排布。
堆叠用于减少占格；不以合并次数为目标。

## 范围与归属

- 统一堆叠包含根容器与带有效规则容器的直属堆叠，允许它们之间转移数量。
- 未打有效规则的容器内部不参与，但可以遍历以找到更深层的合法目的地。
- Locked 物品及 Locked 容器子树跳过；Pinned 保留位置与堆叠身份，只接收数量。
- 游戏决定是否同类、堆叠上限和操作是否合法；不依赖 UIFixes 的合并入口或配置。
- 空间利用率优先；空间收益相同时尽量保留原容器归属，减少跨容器转移。
  保留归属不意味着每个箱子必须保有原数量或至少一堆。
- 收纳规则的优先级用于后续收纳，统一堆叠不局限于根容器向匹配目的地的补充。
  堆叠结束后，以实际剩余物品及其位置进入收纳。

## 执行与失败

- 同容器能够完成的合并优先在容器内进行，再考虑跨容器转移。
- 跨容器转移可以组成链条，共同释放一个或多个堆叠占位。
  没有释放占位收益的转移不为了增加合并次数而执行；Pinned 接收方仍允许补充。
- 所有转移先通过游戏模拟，再逐项提交事务。后续操作使用实际数量，
  不能把计划中的转移当作成功，也不能把失败来源当作已耗尽。
- 失败时记录来源、接收方和原因，重新读取受影响容器的堆叠状态。
  已成功的事务保留，后续转移重新检查实际容量与游戏同类判定。
- 收纳时对已有或新形成的堆叠继续按需补充，未选入布局的同规则候选也参与。
  这一补充不替代收纳前的统一堆叠阶段。

## 示例

| 场景 | 预期 |
| --- | --- |
| 两个带规则箱子各有 30/60 发 | 合为一堆，释放一格，允许其中一箱不再有这批弹药 |
| 每箱各有两个 30/60 发堆叠 | 各自在箱内合并，不为同样收益跨箱转移 |
| 两箱各有 40/60 发且没有 Pinned | 两堆仍需占两格，保留原数量 |
| 三箱各有 40/60 发 | 可经连续补充变为两堆 60/60，释放一格 |
| 容器满了，但 Pinned 堆叠未满 | 可以补充数量，不移动或替换 Pinned 堆叠 |
