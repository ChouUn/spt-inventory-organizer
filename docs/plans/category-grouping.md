# 按类别聚合排布

> Parent: [../index.md](../index.md)
> Status: 层级聚合效果已获用户确认；当前版本可作为功能里程碑，性能待优化
> 依据：[排布契约](../feats/packing.md#按类别聚合)

## 目标

仓库空间压紧后，仍可出现水、枪与背包穿插的情况。
用户已明确父类聚合优先：先让武器整体靠近，再让枪械子类靠近。
在保持空间利用率与占用高度的前提下，按类别树深度逐层优化。

## 实施

- [x] 从快照向排布请求传递 SortType 与类型边界以内的子类别 ID 链，空子链直接归类型根。
- [x] 增加逐层聚合指标、父层优先比较及通用最优界限判断。
- [x] 单网格与多网格共用聚合模型，单格也参与位置求解。
  里程碑采用逐层证明与锁定；后续改为去重后安全联合加权，
  超出数值范围才分段。实现和验收见[联合加权计划](weighted-grouping.md)。
  全部阶段共享单次预算，保持空间与父层严格优先。
- [x] 完成构建、回归和规模验证，核对面积、高度、聚合与固定障碍。
- [x] 复现实际仓库聚合无变化、反复耗满预算的问题，并加入匿名几何回归。
- [x] 构造沿完整类别树排序的初始布局作为全局提示，只采用空间不退步的结果。
  全局矩形模型继续自由求解，仍按空间及父层优先的目标序列比较。
- [x] 移除单类别单格特判；按面积上界、高度下界和各层跨度下界判断退出。
  未选候选通过每类不可避免的装入面积参与界限推导。
- [x] 单网格限时结果在游戏进程内复用，输入或已应用结果变化时失效。
  SortType 与类型内子链按内容比较，实际聚合归属变化时失效。
  最多保存 32 项；多网格联合选择继续照常求解。
- [x] 部署并由用户确认实际仓库聚合效果。

## 验证

回归覆盖空间已最优仍聚合、纯单格、转置覆盖行、固定障碍、
类别缺席、跨网格、面积优先和重复整理稳定性。
规模测试同时覆盖 320 件合成仓库与当前 322 件实际仓库。
实际夹具只保存匿名物品、模板、分类编号及几何数据，
位置来自存档，尺寸来自运行时模组模板、游戏及 Foldables 的尺寸规则。
逐格核对无重叠、无越界，并与游戏日志的面积、高度和类别跨度对照。

游戏内检查仓库、水和背包等类别的聚合表现，核对日志中面积、高度与跨度。
受 1 秒单次和整次 3 秒预算约束，不保证每次都找到改进或证明全局最优。
前一轮多网格、预算与统一堆叠改动继续保留，不将本轮测试代作其游戏内验收。

## 当前结果

- 前版平铺类别在游戏内已观察到仓库跨度 677→247，垃圾箱 51→32。
  首次整理 4.745 秒，第二次 115 毫秒，第二次没有再次移动物品。
  这只证明前版实际执行结果，不代替本轮层级聚合验收。
- 本轮以刚整理后的快照重新计算层级指标：
  `[195,256,117,39] → [59,124,40,21]`，顺序为顶层到深层。
  武器父类跨度 14→7，装备 60→27，饮食 27→4。
- 全部 322 件保留，面积 606 格、可移动高度 61 行、6 个固定障碍不变。
  单网格 1 秒预算下含初始化约 1.1 秒，结果为 `Feasible; level=0`。
  主要收益来自层级初始布局；全局模型未证明顶层最优，不声称全局最优。
- 小规模混合尺寸通过穷举核对面积、高度及父子层目标；
  另覆盖父子利益冲突、多网格、不同深度、非单格候选的通用界限、
  类别链缓存命中及仅父类变化时的失效。
- 完整构建零警告、零错误；Core 132 项与 UIFixes 兼容 4 项测试通过。
- 用户退出游戏后已部署，全部部署文件与构建产物哈希一致，UIFixes 配置未变。

## 后续性能优化依据

并单独测量布局提交内部开销，不以降低聚合质量换取更短等待。
