# 收纳优化：多网格选择、求解预算与堆叠规划

> 当前契约：[../feats/packing.md](../feats/packing.md)

## 目标

提高多网格容器的装入量，避免收纳耗尽最终排布的求解预算，
并减少标签、规则与物品增多时的重复读取和扫描。
从一次整理的整体物品状态出发规划堆叠，保留游戏事务的实际校验和结果反馈。

目标契约见 [堆叠](../feats/stacking.md) 与 [排布](../feats/packing.md)。
用户在确认统一堆叠范围与顺序、提交文档后，授权开始实现。

## 优化前的实现依据

| 路径 | 当前工作方式 |
| --- | --- |
| `StackMerger.MergeContainersAsync` | 容器内排序后双重循环，逐对检查和合并 |
| `StackMerger.TopUpAsync` | 每个来源重新读取来源与目标堆叠，并排序扫描目标 |
| `Organizer.CollectAsync` | 每条规则重新获取候选，执行后刷新完整快照 |
| `Organizer.CollectIntoAsync` | 每个网格刷新快照，分别选择候选和腾位 |
| `Organizer.SolveAsync` | 按调用顺序消耗共享预算，最终排布没有保留额度 |

模板不同的堆叠已在调用游戏同类判定前排除，但仍会经过循环检查。
优化前跨容器补充发生在根容器候选与匹配目的地之间，
不会从一个已收纳的带规则容器抽取数量去补另一个。

## 范围

包含多网格联合选择、阶段预算、一次整理内的物品索引、堆叠规划与增量更新。
既有规则优先级、固定堆叠身份、游戏合并判定和 UIFixes 兼容沿用现有要求。

堆叠来源扩展至带有效规则容器内的堆叠，先统一堆叠，再收纳与排布。
空间利用率与尽量保留原容器归属的关系，见需求第 6 节。

多网格联合分配新收纳候选，堆叠后保留的原有物品
仍留在各自网格内参与重排。
原有物品跨网格搬迁未纳入本次实现。

## 实现方案

### 1. 统一查看物品，按事务结果更新

一次整理内建立物品索引，保留父容器、网格、位置、规则、锁、模板及堆叠数量。
逻辑上统一查看物品，不实际清空容器，也不把锁内或其他范围外物品自动变成候选。
折叠继续按物品自身状态判断，沿用已确认的行为。

按以下顺序组织计算与执行：

```text
读取物品与规则，建立索引
  → 规划并执行折叠，刷新受影响的尺寸与状态
  → 统一规划并执行容器内及跨容器堆叠，更新数量、归属与消失的来源
  → 按规则优先级规划补充、候选余量与多网格落位
  → 执行该规则，更新实际状态，再处理后续规则
  → 使用保留预算进行最终排布
```

堆叠阶段从统一索引中选择合法来源与接收方，包含不同带规则容器内的堆叠。
完成后，以实际剩余堆叠及其位置进入收纳与排布，
不能以必须保留每箱数量为由阻止能释放格子的跨容器合并。
收纳继续按规则优先级执行；新目标堆叠的容量也应纳入本规则推演，
避免只计算移动前已有的接收方。
尚未落地的目标堆叠只是计划；创建失败后，依赖它的补充必须重新判断。

按模板建立堆叠候选分组，减少无关配对；最终是否同类仍调用游戏判定。
不能仅凭模板相同就合并，也不假定其他 mod 的同类判定具有传递性。
每次成功事务更新数量、位置与物品索引；失败时读取受影响状态，重新规划依赖项。
折叠可能改变外层容器尺寸，刷新范围需覆盖实际受影响的祖先。

### 2. 一条规则联合考虑目标全部网格

扩展当前单网格装箱请求，为候选提供可进入的网格集合。
每件候选最多选择一个网格，堆叠后保留的原有物品按所属网格必留，
固定障碍继续固定。
2026-09-10 修正：收纳只最大化装入面积，达到面积上限即停止；
压紧与父子类别聚合只在最终排布执行，详见当前排布契约。

逐网格启发式与现有位置继续提供可行保底，联合求解只采用更优结果。
现有单格数量变量不能直接跨过滤不同的网格共用；
需按可进入网格集合分组，确保还原单格物品时存在合法分配。

应用布局仍通过已有游戏事务通道执行。
某网格腾位失败时，不执行依赖该网格新布局的移动；
成功事务保留，尚未执行的候选按实际状态重新判断。
避免仅因候选已被联合计划选中，就在移动成功前将其从后续规则移除。

### 3. 收纳最多 2 秒，最终排布至少预留 1 秒

收纳阶段最多消耗 2 秒求解预算，最终排布可使用整次 3 秒的剩余额度。
例如收纳用 0.4 秒，最终排布可用 2.6 秒；收纳用满 2 秒，则剩 1 秒。
最终排布继续先处理根仓库，使预留额度能用于仓库布局。

单次联合求解仍最多 1 秒，以目标容器作为一次调用；
其他单网格排布调用也维持最多 1 秒。
达到理论界限或证明最优时提前结束，预算耗尽时使用合法保底。
具体预算边界已同步排布契约。

按实际规划耗时扣减、最多扣除单次分配额度；超额调度与保底开销单独反映在实际耗时中。
不承诺包含游戏事务的整个操作在 3 秒内完成。
日志分别给出收纳与最终排布的耗时、剩余预算及提前退出原因。

### 4. 减少重复工作

规则在一次整理内解析一次；以物品索引维护候选集合与容器成员。
模板、名称和类别等未变的数据复用，数量和位置按事务结果更新。
按物品与规则缓存匹配结果时，需覆盖折叠等可能影响显示属性的失效条件。

堆叠补充直接定位来源，目标只扫描相关模板分组。
跨容器移动后将新堆叠加入目标索引，来源耗尽后立即移除。
减少每条规则和每个网格的全树快照，保留必要的阶段刷新与失败后校准。
游戏对象读取、校验和事务仍在游戏线程执行，后台只处理纯数据。
