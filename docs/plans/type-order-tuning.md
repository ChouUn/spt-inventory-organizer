# 客制化排序的调优开放问题

> Parent: [../index.md](../index.md)
> Status: 待调研
> 依据：[自定义类型顺序契约](../feats/packing.md#自定义类型顺序)

当前实现包含多种初始布局策略和一次局部压紧求解。
本轮保留现有参数；以下问题尚无充分对照数据，不作为本次功能提交的调参任务。

## 开放问题

### 局部压紧的搜索范围

当前把物品纵向移动限制在原位置前后 3 行，以少占至少一行为求解条件。
更远的移动可能产生有效压紧结果，但不在此次局部搜索范围内。

- 固定 3 行是否适用于不同物品尺寸、仓库密度和固定障碍？
- 放宽或取消范围后，新增成功案例是否足以抵偿搜索时间？
- 与直接把全部剩余预算交给全局求解相比，局部压紧是否稳定改善最终布局？

### 时间与并行度

局部压紧每网格最多分配 0.75 秒，并在剩余网格与后续全局求解之间分配剩余额度。
最多使用 8 个 worker，受可用逻辑处理器数限制；随机种子为 0。
多 worker 的调度仍可能使同一输入的结果和耗时变化。

- 0.75 秒上限是否会挤占全局聚合所需的时间？
- 多容器同时需要压紧时，当前预算分配是否合适？
- 不同并行度在低核数与高核数机器上的收益、波动和 CPU 开销如何？

### 初始布局策略的独立收益

当前尝试整体及局部镜像、横向分带重排、循环移位，
以及从两个方向按三种朝向偏好生成的贪心和逐类型布局。
横向分带按带内最大物品的类型排序。

- 哪些策略实际被选中，并改善最终结果？哪些只是增加预处理耗时？
- 分别关闭策略后，完整布局成功率、占用行数及各层类别跨度如何变化？
- 分带内混有多种类型时，按最大物品决定顺序是否稳定有效？

## 已知待调优样本

2026-09-12 使用同一份 322 件物品的真实仓库快照，以 2.5 秒预算回放：

| 顺序 | 清理前行数 | 清理后行数 |
| --- | --- | --- |
| SM 推荐顺序 | 61 | 61 |
| 护甲、胸挂、武器前移，其余按 SM 推荐顺序补齐 | 62 | 62 |

两种顺序在两个版本中都完整放入且没有类型反序。
第二组的局部压紧均在时限内返回 `Unknown`，未找到少占一行的布局。
该输入与已有“其余类型按 SMH 顺序补齐”的护甲优先回归不同；后者仍通过 61 行检查。
这组同输入对照用于记录调优问题，不作为不同版本的性能结论。

## 验证方式

使用多份真实快照，覆盖推荐顺序、SMH 顺序、反转顺序和单独前移类型，
并包含不同填充密度、固定障碍及多容器场景。
逐项改变策略或参数，在相同总预算下多次独立运行。
记录候选生成、局部压紧和全局求解的耗时，以及最终成功率、行数和各层跨度。
每次验证物品守恒、几何合法、固定位置、网格归属与类型顺序。
对照结果形成报告后，再决定删减策略或修改参数。
